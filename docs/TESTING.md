# Хүлээн авах тест — ISM Digital Museum

Дараах алхмуудыг **Supabase project холбогдсоны дараа** хоёр өөр шинэ хэрэглэгч, нэг админтай орчинд шалгана:

1. Зочин Нүүр, Багш нар, Арга хэмжээ, Timeline руу орж, хуудас refresh хийнэ. Зураг алдаагүй гарна.
2. Багшийн профайлд нэр, албан тушаал, мэйл, боловсрол таарч буй эсэхийг шалгана.
3. Хайлт хоосон үр дүнтэй үед `Илэрц олдсонгүй` гарч, `Бүгд` шүүлт ажиллана.
4. User A бүртгүүлж, нэвтэрч, бүтээл зурагтай нь нэмнэ. `pending` төлөвтэй харагдана.
5. Зочин `pending` бүтээлийг үзэхгүй; user A студидээ харна.
6. User B нэвтэрч user A-ийн бүтээлийг UPDATE, DELETE хийхэд Postgres RLS зөвшөөрөхгүй.
7. User A REST API-аар `status='published'` тохируулах оролдлого `403` эсвэл RLS зөрчлийн алдаа өгнө (бодит error code API тохиргооноос хамаарч болно).
8. User A зөвхөн `museum-assets/exhibits/<user A id>/...` руу upload хийж чадна; user B-ийн folder руу upload зөвшөөрөгдөхгүй.
9. Админ SQL Editor-оор `museum_admins` хүснэгтэд нэмэгдсэний дараа pending exhibit-г publish хийнэ; зочин харах ёстой.
10. Админ багш/арга хэмжээ нэмэх, засах, устгах; энгийн хэрэглэгч REST API-аар тэдгээрийг өөрчилж чадахгүй.
11. Form validation, 5MB-аас том файл, буруу төрлийн файл дээр ойлгомжтой алдаа гарна.
12. 375px мобайл, 768px таблет, 1440px desktop дээр хэвтээ overflow болон navigation шалгана.
13. Vercel URL дээр `/teachers/<id>` page refresh хийж 404 болохгүйг шалгана.

Эдгээр нь хийх ёстой тестүүдийн checklist болохоос одоогоор ажиллуулсан гэж үзэхгүй.
